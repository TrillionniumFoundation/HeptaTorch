# Fixed cat metadata reference: ten observations

This package preserves one completed observation on the pinned PyTorch 2.15.0+cpu wheel with Python 3.12.3. The producer, report, public execution receipt, staging receipt, stdout and stderr are copied without rewriting any byte or any recorded path. The report contains ten actual cat recipes and nine requested backward observations. It makes no native capacity or whole-project qualification claim.

`manifest.json` binds the archive and all fifteen regular members by byte count, SHA-256 and the packaged physical file mode. `input_path_map` maps exactly the ten original absolute keys in `report.inputs` to ten unique archive members. `execution_relative_path_map` maps the original public receipt artifact names to their corresponding members. These mappings describe portable copies; the original execution paths remain in their original JSON and source bytes.

The four oracle support inputs, four original fixture files and the byte-identical Python executable are present for physical identity checks. The Python member is retained as evidence and is never executed during packaging or pure readback. The full private process-service receipt is excluded; its original identity remains in the unchanged public receipt.

A reader can verify member identities, all ten mapped report inputs, the fixed eleven provenance checks, both complete process streams, and producer/report/execution bindings without importing Torch or executing the producer or interpreter member. Packaging is a custody operation and adds no native or Torch execution.
