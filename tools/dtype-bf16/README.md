# HIA native bfloat16 conversion

This isolated CPU machine-code component handles raw floating-point bit conversion with no Python or numerical library in its production executable. The scope is **not** complete PyTorch dtype support. It intentionally avoids the numerics core, owned-storage and ABI2 worktrees while those have active owners.

The wire contract is little-endian `u32 mode`, `u32 count`, followed by exact packed data. Mode 0 converts 32-bit float bits into 16-bit bfloat16 bits using round-to-nearest, ties-to-even; mode 1 widens 16-bit bfloat16 bits into 32-bit float bits. The output begins with `u32 status` (0 for valid, 1 for refused) then the packed converted values. Counts above 200,000, unknown modes, truncation, excess input and insufficient capacity are refused. Rounding of a NaN sets the quiet bit, with sign and upper payload preserved; exact NaN payload equivalence with upstream remains unclaimed.

The dedicated workflow cold-reproduces the pinned native Hepta compiler, compiles this HIA source twice to byte-identical Linux ELF executables and runs them with `PATH=` against an independently installed, hash-pinned official CPU PyTorch 2.15.0 wheel. The native program never calls Python, NumPy or PyTorch. The 22-case real-PyTorch differential includes all 65,536 bfloat16 words, 16-bit rounding tie patterns, positive/negative zero, infinities, subnormals, seeded random float32 words, empty inputs and refusal cases. All non-NaN numerical outputs require bitwise exact equality; NaNs require classification only.

See `validation/hosted-native-bf16.json` for actual immutable hosted run identities and a retained prior CI failure. The frozen full acceptance remains HOLD and all 2,590 upstream schemas plus 17 subsystem gates stay in scope. Integration with general Tensor/Storage dtype dispatch, scalar promotion, AD and non-CPU devices has not occurred.
