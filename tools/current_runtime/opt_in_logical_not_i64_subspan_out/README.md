# logical_not(out=): I64 dense nonzero-offset subspan

Adds public I64 dtype 2/width 8 to the existing positive-offset admission for disjoint direct-root dense permutation destinations. It requires a multiple-of-eight byte offset, retaining existing Bool/F32 alignment and the root, rank, shape, density, owner/version, live storage and tagged address span checks. The reversible projection changes only the exact helper body; the partition checker verifies that all other bodies, calls and declarations are unchanged. F64 positive offset remains refused.

The exact published Bool predecessor was rebuilt, then two separate cold builds reproduced the same candidate ELF. The fresh official locked CPU PyTorch process generated four added I64 rows with signed 64-bit extrema, three independent coordinate masks in a non-end span and one right-boundary case. All twenty prior official rows verify unchanged. The candidate native no-Torch capture passed all twenty-four layout rows; the exact predecessor constructed and refused all four new layouts with full rollback. The pure reader checked eighty-five complete rollbacks, including both distinct-handle same-start and partially overlapping I64 views sharing Storage/Version, canaries, unchanged source, handle identity, one shared version increment and the exact eight-byte extent. The original retained-79 native and independent raw replay passed on this same ELF, including all eighty-two rollback controls and its unchanged 876 response and request frames. No setup refusal or skipped case was counted.

`prepare_i64_subspan.py` consumes the exact projected Bool predecessor source, new path, build.py and optional candidate discovery receipt. The supplied pinned manifest locks all object identities. `derive_tests.py` regenerates observers from the prior Bool package; official and native arguments are unchanged. Retained79 uses the original numeric-self fixture and unchanged independently decoding reader. The evidence file binds the exact receipts and raw frames; the complete synthetic raw evidence is held separately on Dot. This is opt-in scoped local evidence, not a hosted aggregate or a default/runtime activation.
