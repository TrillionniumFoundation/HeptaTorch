# CPU where.self: true rank-zero I64 with dimensional F32

This opt-in extension admits a true rank-0 ordinary public CPU I64 tensor (shape [] and exactly one element) and a positive-rank ordinary canonical F32 value, either placement, with ordinary Bool condition and compatible nonempty result. It uses the existing direct integer-to-F32 RN-even cast and preserves every selected F32 word. Empty results, opposite rank role, both rank zero, other mixed scalar-shaped pairs, views, Python scalar overloads, and default activation remain outside this new scope. Existing F64 canonical empty and nonempty behavior is retained.

The locked Torch oracle observed 438 cases/10,388 words; all match independent native physical metadata, bytes and owner readback. Direct true scalar casts covered 216 values including 20 where F64 intermediate provably and physically changed results. Native observer uses no Torch. Exactly two historical old I64-scalar/F32-dimensional rejections were matched by exact real operands; four opposite-role/both-rank0 historical rejections remain. Full previous streams were matched except those two precise replacements. The pressure check keeps the original request hash, lead/recovery packets and absolute address-space cap.
