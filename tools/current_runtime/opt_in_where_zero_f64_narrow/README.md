# CPU where.self: true rank-zero F64 with dimensional F32

This opt-in HIA path admits exactly one ordinary scalar-shaped public F64 CPU tensor (rank 0, count 1) plus one dimensioned nonempty F32 tensor in either order, with an ordinary Bool condition and compatible nonempty broadcast. Inputs must be canonical and meet the existing owner and storage checks. Output is fresh F32. Selected F32 words are unchanged, including signaling NaN bits. A selected F64 uses the existing round-to-nearest-even narrower for non-NaNs and the locked PyTorch CPU sign, quiet bit and high payload mapping for F64 NaNs. The global HIA narrowing helper and all prior where paths are unchanged.

Official pinned CPU PyTorch verified 254 boundary, infinity and NaN cases / 4,980 outputs, with 124 distinct direct rank-zero casts. Ten archived input sets were separately matched against locked PyTorch and native HIA (24 output words); two finite rows also appear in the preregistered board, and two additional archived frames repeat those same operands with independently verified wire and owner state. Locked and mathematical predictions agree. Of the base NaN board, the locked payload mapping differs from the inherited global canonical result on 28 cases / 280 selected words, with locked quieting on F64 conversion and exact raw identity for F32 selections. Native HIA and the independent no-Torch reader verified all 264 executions and 5,004 words, metadata, input stability, freshness, lifetime and rollback. Exact parent refused all 264. Twelve exact old wire refusals changed (ten distinct archived operand tuples), and every other retained frame and refusal was replayed unchanged under the original pressure bound.

Not covered: empty outputs on this new route, mixed both-rank-zero values, transposed/view/grad inputs, wrapped Python scalars, other new rank-zero dtype pairs, other devices, or default activation. No complete PyTorch rewrite claim.
