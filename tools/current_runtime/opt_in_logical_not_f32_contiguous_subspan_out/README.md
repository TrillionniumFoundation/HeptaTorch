# logical_not(out=): F32 contiguous positive-offset subspan

Adds only a direct-root retained row-major contiguous F32 destination with a positive byte offset. Requires dense layout, exact F32 dtype 0/width 4 and existing four-byte alignment, shape, rank, positive strides, roots, disjoint owners, version and live byte/element/tagged-address extent constraints. The reversible projection changes only the existing density helper. Zero-offset retained contiguous F32 and positive-offset contiguous Bool/I64/F64 remain refused. Default activation, constructors and resize are unchanged.

Two independent cold builds reproduced one exact candidate ELF. The exact F64 permutation predecessor constructed all four new F32 layouts before refusing and fully rolling back the writes. The separate official locked CPU PyTorch process produced 32 total fixtures, retaining the prior 28 unchanged. New rows cover three independent masks in a [2,3]/[3,1]/offset2 view over [10] with outside sentinels, and one view ending exactly at the right boundary.

Native execution without Torch and independent raw decoding matched all 32 positives. It also verified the unchanged four unsupported contiguous-view routes using actual shape, stride, dtype, displacement and shared-ownership class. Success checks include unchanged source, unchanged byte canaries outside the span, one shared Version bump, exact handle identity and byte-level reference. The separate original retained-79 replay passed all 79 successes and 82 rollbacks using identical 876 request/reply frames. No constructor refusal was counted as test coverage.
