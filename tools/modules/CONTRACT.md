# Borrowed HIA modules: native contract

Status: implemented in native HIA and qualified for the boundary below.
This is a separately identified extension
of Hepta commit `f33d8da316de8fdf27b504371f1a5310997ff548`, not an existing
upstream import capability. No upstream checkout or canonical HeptaTorch source
is changed by the authoring adapters.

## Actual upstream boundary

The upstream compiler's [public export checker](https://github.com/TrillionniumFoundation/Hepta/blob/f33d8da316de8fdf27b504371f1a5310997ff548/tools/hia_selfhost_exports.py)
accepts only scalar parameters and zero/one scalar results. Its legacy
`selfhost_elf` f0 instead has a real six-word SysV borrowed-buffer wrapper.
[The compiler implementation](https://github.com/TrillionniumFoundation/Hepta/blob/f33d8da316de8fdf27b504371f1a5310997ff548/tools/generate_hia_selfhost.py)
already stages each internal parameter in a 16-byte slot, passes the argument
area in `rdi` and the result area in `rsi`, and transfers both pointer and length
for borrowed buffers. `loan_call` rejects mutable root aliases and suspended
parents, while exact callee signatures and effects are checked at every call.

The only upstream external calls are closed `calloc`/`free` calls in the
[owned ELF emitter](https://github.com/TrillionniumFoundation/Hepta/blob/f33d8da316de8fdf27b504371f1a5310997ff548/tools/hia_selfhost_owned_elf.py).
The existing [native HIA linker](https://github.com/TrillionniumFoundation/Hepta/blob/f33d8da316de8fdf27b504371f1a5310997ff548/tools/generate_hia_elf_linker.py)
does resolve exact ELF names and validate symbolic relocations. Its
[documented contract](https://github.com/TrillionniumFoundation/Hepta/blob/f33d8da316de8fdf27b504371f1a5310997ff548/docs/HIA_NATIVE_ELF_LINKER.md)
requires a zero-argument scalar C entry and explicitly does not infer checked
function signatures from ELF symbols. Therefore merely relaxing the scalar
export check would not provide a valid borrowed module boundary.

## Admitted source and ABI

1. An explicit module has ordinary HIA function bodies, an `exports(...)` list,
   and real `fn name(params) -> (results) effects(...) external()` declarations
   for dependencies. An external declaration has no placeholder body and emits
   no executable implementation. It is permitted only in module object output.
2. Published and imported parameters are exact scalar types other than `unit`, or `readbuf` /
   `mutbuf`; results are zero or one scalar/unit. Owned `buffer` / `chain`,
   allocation, and borrowed-resource results at the module boundary are
   rejected in this initial profile. This covers the current HeptaTorch tensor
   arena and its real buffer-bearing operations; it does not cover all future
   PyTorch ownership or allocation requirements.
3. Calls use the pinned compiler's internal descriptor ABI: `rdi` points to
   16-byte argument slots and `rsi` to result slots. Scalars occupy the first
   word, normalized to their HIA type. Borrowed resources occupy `(pointer,
   length)` and do not transfer allocation ownership. Both callers and callees
   are generated by the same admitted compiler profile.
4. The whole executable has exactly the existing public entry signature
   `(readbuf,mutbuf,mutbuf) -> u32`. A native startup creates three disjoint
   live 1 MiB buffers, calls the selected entry, and handles the existing
   stdin/stdout/status protocol. Internal module exports are not advertised as
   arbitrary foreign C APIs.
5. Each producer is checked by the actual native HIA compiler. Type identity,
   required effect subsets, mutable alias rejection, parent suspension,
   resource CFG joins, and local-loan cleanup remain mandatory. Shared read
   aliases remain permitted. A scalar error result does not consume a caller's
   borrowed descriptor. Traps retain the existing process-terminating UD2
   semantics; no implicit rollback or exception cleanup is introduced.

## Native link admission

The object emitter writes an explicit `.hia.interface` section identifying
the descriptor ABI and every imported/exported symbol's ordered parameter
types, result type/count and complete declared effect set. The native HIA linker
gate independently parses that section and matches exact symbol bytes and
the complete interface, not a host-side manifest comparison.

The gate rejects undefined imports, duplicate definitions, imports of private
functions, mismatched arity/types/effects/ABI, forbidden resource interfaces,
malformed metadata, unsupported or overlapping fixups, and cyclic module
dependencies. Module DAG admission is intentionally conservative; a cycle of
module dependencies is rejected even if the aggregate function graph might be
acyclic. Native internal call checks remain mandatory within each module.

Imported calls use actual `R_X86_64_PLT32` symbolic relocations with addend -4,
resolved directly by the native static linker. The entry is looked up by exact
symbol name and independently required to have the public three-buffer/u32
signature. No compiler/linker output is published before admission completes.

## Trust and custody

Untrusted HIA source and malformed module objects are refusal-test inputs.
The source compiler is responsible for body typing, effects, ownership and
emission. The linker is responsible for object structure, interface agreement,
module graph and relocations. The linker is not a machine-code verifier: a
malicious person who can replace an admitted object's code and metadata can
forge compiler assertions. Reproducible compiler/source/object hashes and the
build pipeline's custody bind the objects used by this project to the pinned
native compiler. This does not claim cryptographic compiler attestation.

The outer native entry owns valid, disjoint allocations. No interface claims
to validate arbitrary foreign pointer provenance or liveness. The current
runtime receives packet bytes and offsets, never host pointers. Python may
author development source, assemble test packets, and observe independent
reference results; it must not implement tensor kernels, resolve production
module signatures, or perform production ELF linking.

## Qualification scope

The actual HeptaTorch function inventory is partitioned into a borrowed-buffer
kernel unit and runtime unit without changing function bodies. The independent
units compile and link with native HIA and execute the tensor, gradient,
optimizer and graph-lifetime fixture suite. The tests in this directory also
execute cross-unit mutation and shared read aliases and refuse mutable aliases,
expired loans, effect/signature mismatches, private/undefined names and corrupt
relocations. A separate guarded flat-ABI observer checks dirty workspaces and
output failure atomicity. Test receipts bind exact source, compiler and image
hashes; fixture counts change as the runtime grows. Unresolved dimensions stay
in the full-project ledger.

The linker admits up to 64 modules with at most 256 function records per unit.
This removes the single-compilation-unit function ceiling; it does not make
source or output storage unbounded. Acyclic calls can span units, so the former
single-unit 256-frame bound is not a whole-program stack bound. This profile
does not prove total stack cost, implement recursive module graphs, admit heap
ownership transfers, or establish all PyTorch semantics.
