## Two separate operations

The root executor supplies the complete source-manifest SHA explicitly.

    /usr/bin/python3 -I -S -B supplement.py \
      --package-sha256 ACTUAL_SOURCE_MANIFEST_SHA \
      --runs-root /home/qian-qi/heptatorch-continuation-20261116/runs \
      --output NEW_SEAL_DIRECTORY \
      --seal

This operation seals custody only. It writes a complete.tar.xz, file-manifest,
seal-plan, report and evidence-binding in a fresh directory. It never constructs
a native Session or executes a Tensor program, compiler or Torch. Failure leaves
the complete attempted output intact and produces a FAIL report. A later binding
write failure is saved separately without overwriting a completed custody report.

## Paths, modes and future portability

Current admission intentionally requires the original ROG runs root. It does not
silently rewrite absolute input paths. A later repository adapter must explicitly
map carrier members, source paths, original modes and Git installation modes,
then reproduce and verify all source/build outputs. The original source-install
map gives the complete 112-file publication mapping.

Original files and directories are archived with their original modes. Only the
synthetic inputs and execution containers use mode 0700. The program writes
new outputs under umask 0077. Every source file and original input is rehashed
before completion. Original native input-custody records do not contain modes;
the program does not invent them, and records the actual copy modes in the new
member inventory. Future Git normalization must be recorded separately.

Both entry modes are guarded against processes, Torch/native library loading,
network connections, live /proc and resource-limit changes. They never call the
original native main functions. Source authoring has not executed Python, AST,
an emitter, compiler, native code, Torch, sealing or admission.
